# 개발 계획 (Phase별 목표 초안)

> 각 Phase는 **직접 실행하고 테스트할 수 있는 동작하는 SW**를 목표로 한다.
> Phase가 완료될 때마다 고객 피드백을 받고 다음 Phase로 진행한다.

---

## Phase 1 — 실행되는 메뉴 화면

### 개발 목표
콘솔을 실행하면 CRUD 메뉴가 표시되고, 번호를 선택할 수 있다.
아직 기능은 동작하지 않아도 되며, 메뉴 선택 시 "준비 중" 메시지를 출력한다.

### 고객 확인 포인트
- 프로그램이 오류 없이 실행되는가
- 메뉴 항목(Create / Read / Update / Delete / 종료)이 화면에 잘 표시되는가
- 번호를 잘못 입력했을 때 프로그램이 죽지 않고 다시 메뉴로 돌아오는가
- 종료(0번)를 선택하면 정상적으로 프로그램이 끝나는가

---

## Phase 2 — 회원 등록 및 전체 목록 조회

### 개발 목표
회원을 새로 등록하면 `members.json` 파일에 저장되고,
전체 목록 조회 시 저장된 회원이 화면에 출력된다.
프로그램을 재시작해도 이전에 등록한 회원이 유지된다.

### 고객 확인 포인트
- 회원 등록 시 이름·이메일·전화번호 등을 입력할 수 있는가
- 등록 후 `members.json` 파일이 생성되고 내용이 올바른가
- 전체 목록 조회 시 등록한 회원이 표 형태로 출력되는가
- 프로그램을 껐다 켜도 이전 데이터가 그대로 유지되는가
- 아무 데이터도 없을 때 목록 조회 시 적절한 안내 문구가 표시되는가

---

## Phase 3 — 회원 수정 및 삭제

### 개발 목표
등록된 회원의 정보를 수정하거나 삭제할 수 있다.
삭제 시에는 실수 방지를 위해 확인 절차를 거친다.

### 고객 확인 포인트
- 수정 시 ID를 입력하면 해당 회원의 현재 정보가 먼저 표시되는가
- 수정할 필드만 선택해서 바꿀 수 있는가 (바꾸지 않을 필드는 그대로 유지되는가)
- 수정 후 `members.json`에 변경 내용이 정확히 반영되는가
- 삭제 시 "정말 삭제하시겠습니까? (Y/N)" 확인 절차가 있는가
- 존재하지 않는 ID로 수정·삭제 시도 시 오류 메시지가 출력되는가

---

## Phase 4 — 검색 및 전체 완성

### 개발 목표
ID 외에 이름·이메일 등 특정 필드 값으로도 회원을 검색할 수 있다.
잘못된 입력, 빈 값, 중복 이메일 등 예외 상황을 안정적으로 처리한다.

### 고객 확인 포인트
- ID 검색과 이름/이메일 키워드 검색이 모두 동작하는가
- 검색 결과가 없을 때 적절한 안내 메시지가 표시되는가
- 필수 입력값(이름, 이메일 등)을 비워두고 등록 시 오류 처리가 되는가
- 여러 회원을 연속으로 등록·수정·삭제해도 데이터가 꼬이지 않는가
- 전체적인 사용 흐름이 자연스럽고 불편한 부분이 없는가
